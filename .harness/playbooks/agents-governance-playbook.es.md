# Playbook de Gobernanza de Agentes

## Cuándo Usarlo

- al crear o actualizar `AGENTS.md`
- al evolucionar reglas del harness
- al promover lecciones de satélites a guías corporativas

## Verificaciones Obligatorias

1. `AGENTS.md` refleja el rol actual del proyecto o repositorio.
2. Los comandos de build, test y ejecución siguen siendo válidos.
3. Las descripciones del stack coinciden con los perfiles autoritativos actuales.
4. Los errores repetidos de agentes se promueven a reglas explícitas.
5. Se agregan nuevos playbooks cuando una misma auditoría o flujo de trabajo se repite entre repositorios.
6. Las lecciones de repositorios satélite se generalizan antes de promoverlas a estándares corporativos.

## Regla de Promoción

Si un problema se repite en múltiples repositorios o múltiples ciclos de auditoría, conviértalo en:

1. una regla,
2. un paso de playbook, o
3. una actualización de estándar específico de runtime.
