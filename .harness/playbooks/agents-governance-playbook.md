# Agents Governance Playbook

## Use When

- creating or updating `AGENTS.md`
- evolving harness rules
- promoting satellite lessons into corporate guidance

## Mandatory Checks

1. `AGENTS.md` reflects the current project or repository role.
2. Build, test, and run commands are still valid.
3. Stack descriptions match current authoritative profiles.
4. Repeated agent mistakes are promoted into explicit rules.
5. New playbooks are added when the same audit or workflow repeats across repositories.
6. Satellite repository lessons are generalized before promotion into corporate standards.

## Promotion Rule

If a problem repeats across multiple repositories or multiple audit cycles, convert it into:

1. a rule,
2. a playbook step, or
3. a runtime-specific standard update.
