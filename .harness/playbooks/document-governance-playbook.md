# Document Governance Playbook

## Use When

- reviewing requirements
- updating functional stories
- editing ADRs or blueprints
- validating bilingual sync

## Mandatory Checks

1. Functional content is readable to Product Owners and Business Analysts.
2. Technical implementation detail is isolated in `Technical Requirements` or equivalent technical sections.
3. English and Spanish variants stay synchronized.
4. Diagram labels match document language.
5. Runtime-specific claims point to the correct authoritative profile.
6. Multi-tenancy descriptions preserve the primary application layer and secondary database failsafe model.
7. Parametric catalogs and configuration entities follow the `code`, `value`, `description` minimum contract when applicable.

## Standard Audit Output

- artifact
- location
- issue type
- severity
- recommended correction
