## BLOCKED — needs the maintainer

### 1. Trigger the npm release for `core-domain@1.3.0`

The code is done and the planner confirms the shape. Nothing else in W2/W3 can proceed until
this is on the registry.

- Run `npm-release.yml` with **`dry_run=true` first**, read the log, then publish.
- The planner, run against the real registry, reports: **1 of 8 packages would publish, and it
  is `@beyondnet/evolith-core-domain@1.3.0`.** The other seven are already there and are skipped.
- Why it must go alone: HEAD's CLI imports six `core-domain` subpaths that 1.2.0 does not ship.
  Publishing the CLI first would fail its own smoke gate, correctly.

### 2. `npm deprecate` the dead `@evolith/*` scope

- `@evolith/sdk@1.0.0` is **not deprecated at all**; `@evolith/core@1.0.0` carries a message
  that names no successor. Between them ~49 installs a month go into a dead end.
- **Blocker: the local npm token cannot write.** `npm whoami` returns `beyondnetperu` and
  `npm view … maintainers` lists that account, but `GET …?write=true` returns 200 while
  `PUT https://registry.npmjs.org/@evolith%2fsdk` returns **404**, which is npm's shape for
  "no permission". Real publishes go through Actions OIDC, which is why this was never noticed.
- Fix: a token with write scope, or do the deprecate from a workflow. Creating or changing npm
  tokens is account configuration and is not something Claude can do.
